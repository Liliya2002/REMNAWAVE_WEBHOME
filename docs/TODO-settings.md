# Что вынести в админку (/admin/settings)

Составлено 31.07.2026. Цель — убрать необходимость лезть на сервер и
перезапускать backend ради изменения настройки.

Общее правило для всех пунктов: **оставлять откат на `.env`** (как в
`services/paymentSettings.js`) — существующие установки продолжают работать
без переноса, значения из админки получают приоритет.

## 1. Параметры мониторинга VPS — В РАБОТЕ

Вкладка «VPS» → подраздел «Параметры мониторинга».

```
VPS_HEALTH_INTERVAL_MIN=10      как часто пинговать
VPS_HEALTH_PING_PORT=22         какой порт проверять
VPS_HEALTH_CHECK_NODES=3        сколько внешних узлов check-host
VPS_HEALTH_PARALLELISM=2        параллельность проверок
VPS_HEALTH_CHECK_ENABLED        вкл/выкл health-check
VPS_EXPIRY_NOTIFY_HOUR_UTC=10   час напоминаний об оплате
```

Важно: крон читает `process.env` один раз при старте, поэтому после сохранения
нужен `reschedule()` — иначе изменения применятся только после перезапуска.

## 2. Параметры триала — сейчас захардкожены в КОДЕ

`backend/config.js`:
```js
FREE_TRIAL_DAYS: 7,
FREE_TRIAL_TRAFFIC_GB: 10,
```

Это даже не `.env` — чтобы изменить срок или трафик пробного периода, нужна
пересборка образа и деплой. Чисто бизнесовая настройка, менять будут часто.

## 3. SMTP / почта

```
SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, SMTP_FROM
```

Делается по готовому образцу `paymentSettings.js`: шифрование пароля,
кнопка «отправить тестовое письмо».

## 4. Интервалы фоновых задач + их статусы

```
CRON_EXPIRE_INTERVAL_MIN=5        проверка истёкших подписок
CRON_TRAFFIC_SNAPSHOT_HOURS=24    снимки трафика
SELECTEL_BALANCE_INTERVAL_MIN=60  проверка баланса Selectel
```

Полезно рядом показывать: когда задача отработала последний раз, сколько
заняла, были ли ошибки. Сейчас это видно только в логах.

## 5. Traffic-агент

```
TRAFFIC_AGENT_SSH_USER=traffic-agent
TRAFFIC_AGENT_SSH_PORT=22
TRAFFIC_AGENT_SSH_TIMEOUT_MS=10000
```

## Выносить НЕЛЬЗЯ

| Переменная | Почему остаётся в `.env` |
|---|---|
| `PGHOST`, `PGUSER`, `PGPASSWORD` | нужны, чтобы прочитать настройки — курица и яйцо |
| `ENCRYPTION_KEY` | им шифруются сами настройки; хранить внутри зашифрованного бессмысленно |
| `JWT_SECRET` | смена разлогинит всех; в БД это лишний вектор атаки |
| `PORT`, `CORS_ORIGINS`, `DOMAIN`, `FRONTEND_URL` | читаются при старте, до подключения к базе |
| `IMAGE_NAMESPACE`, `VERSION`, `DEPLOY_TOKEN` | инфраструктура деплоя, а не приложения |

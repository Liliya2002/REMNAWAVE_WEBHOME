# Идеи: управление нодами RemnaWave и VPS

Список составлен 31.07.2026 после обзора текущих возможностей. Отсортирован по
пользе. То, что уже реализовано (SSH-команды, установка/обновление ноды,
traffic-агент, health-check, история, аналитика, привязка к Yandex Cloud),
сюда не входит.

## Приоритет 1 — закрывают реальные боли

1. **Метрики хоста VPS** (CPU / RAM / диск / uptime). Сейчас известно только
   «отвечает или нет». Не видно, что кончается диск или сервер задыхается по CPU —
   а это предшествует падению ноды. Сбор по SSH раз в 10 мин, история, спарклайны
   в карточке, алерт при диске >85% и CPU >90%.

2. **Авто-восстановление ноды.** Health-check видит падение, но не лечит.
   Логика: недоступна два тика подряд → `docker compose restart` по SSH → если
   помогло, уведомление «восстановлена автоматически», иначе тревога.

3. **Диагностика подключения при ошибке SSH.** `ssh2` пишет «Timed out while
   waiting for handshake», даже когда TCP-соединение не установилось вовсе — это
   уводит не туда (проверено на практике, потеряли час). Перед подключением
   проверять доступность порта и писать точную причину.

4. **Логи ноды из админки.** `docker compose logs --tail=200` по кнопке с
   live-обновлением, без захода по SSH.

## Приоритет 2 — экономят время и деньги

5. **Автопродление VPS через API провайдера.** RUVDS умеет
   `POST /v2/payments/balance` (продление с баланса), Selectel и YC подключены.
   Сейчас только напоминания, дальше руками. Продлевать за N дней до `paid_until`
   с лимитом суммы и подтверждением для дорогих.

6. **Массовые операции.** Обновить ноды на всех VPS, выполнить команду на группе,
   перезапустить по фильтру. С предпросмотром списка и подтверждением.

7. **Бэкап конфигов перед изменением.** Сохранять `docker-compose.yml` ноды и
   xray-конфиг перед правкой, откат в один клик. Сейчас правка необратима.

8. **Трафик по нодам в карточке сервера.** `getNodesBandwidthStats` уже
   используется в разделе «Трафик», но в карточке VPS этих данных нет.

## Приоритет 3 — удобство

9. **Уведомления по нодам RemnaWave.** Telegram-алерты есть только по VPS.
   Добавить: нода отключилась в панели, версия устарела, трафик обнулён.
10. **Web-терминал** — интерактивная консоль через websocket.
11. **Проверка портов и TLS** — расширить внешнюю проверку (check-host) на
    произвольные порты и срок сертификата.
12. **Ротация SSH-ключей** на группе серверов.
13. **Экспорт инвентаря** в CSV/JSON (серверы, стоимость, сроки).

## Приоритет 4 — стратегическое

14. **Автозамена умершего сервера.** VPS недоступен сутки → создать новый через
    API провайдера → развернуть ноду → переключить в RemnaWave → погасить старый.
    Все кирпичи уже есть, нужен сценарий.
15. **Дрейф конфигураций** — сравнение настроек нод между собой с подсветкой
    расхождений.

## Рекомендованный порядок

Сначала связка **1 + 2 + 4** — единый блок «здоровье сервера»: перестаём узнавать
о проблемах от пользователей, часть неполадок чинится сама.
Затем **5** — про деньги и риск потерять сервер из-за забытой оплаты.
